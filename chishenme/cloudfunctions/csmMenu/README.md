# csmMenu · 今天吃啥 家庭菜单云函数

一个函数，按 `event.action` 分发。**不用建七八个小函数逐个部署**。

## 为什么所有写操作都走云函数

客户端只读（为了 `watch` 实时推送），写一律经过这里。原因：

1. 客户端拿不到别人的 openid，也没法校验「这个房间码到底存不存在」；
   云函数里用 admin 权限先查后写，逻辑才可信。
2. 「谁点的菜」需要 `openid → 家庭 → 称呼` 的映射，只有服务端知道。
3. 客户端能写的话，`qty` 传个 `999999` 也没人拦。校验必须在服务端。

## 两个集合

| 集合 | 用途 | 权限 |
| --- | --- | --- |
| `csm_families` | 房间、成员、称呼映射 | 所有用户可读，仅创建者可读写 |
| `csm_menus` | 今日菜品、份数、谁点的 | 所有用户可读，仅创建者可读写 |

### 为什么权限要放开「所有用户可读」

`watch` 走的是**客户端直连数据库**的实时通道，集合读权限对它生效。
如果设成「仅创建者可读写」，客户端就只能收到自己写的那几条 —— 家人点的菜**一条都收不到**，
「家人点菜我能知道」这个核心需求直接失效。

### 为什么放开读也不会被乱写

`csm_menus` 里的文档全部由云函数以 **admin 权限**写入，`_openid` 字段是空的。
而「仅创建者可写」的判定依据就是 `_openid` 与当前用户是否一致 ——
**没有创建者，就没有任何客户端能改它。** 写权限被天然收口到云函数。

### 代价（已知并接受）

「所有用户可读」意味着理论上有人可以绕过小程序直接查这个集合，看到别人家的菜单。
里面只有菜品 id、份数和家人称呼，没有手机号、地址、支付信息。
对一个家庭点菜应用，这个取舍是划算的；换成有隐私数据的产品，就得改成轮询云函数。

## 时区坑（已经处理）

云函数默认跑在 **UTC**。北京时间晚上 8 点以后，UTC 和东八区不是同一天。
如果直接用 `new Date()` 算「今天」，**晚上点的菜会被存成「明天」**。

所以 `todayStr()` / `daysAgoStr()` 严格用 `Date.now() + 8h` 再取 UTC 字段，
和客户端 `utils/format.js` 用的是同一套算法，两边永远不会吵架。

## 菜单的「一天」只到 22:30（menuDayStr）

菜单不是按自然日清空的，而是**每天 22:30 翻篇**：菜单的「一天」是 `00:00 ~ 22:30`。
22:29 打开今天的菜单还在，22:30 一到就空了。

实现上不需要真去删数据 —— 算日期时多往后推 `24 - 22.5 = 1.5` 小时，
等价于把一天的分界线从 0 点挪到 22:30：

| 北京时间 | `menuDayStr()` | 结果 |
| --- | --- | --- |
| 22:29 | 当天 | 今天这份菜单还有效 |
| 22:30 | 次日 | 今天这份作废（**清空**） |
| 次日 08:00 | 次日 | 新菜单就属于这一天 |

菜单相关的读写（`addDish` / `setQty` / `setNote` / `clearMenu` / `listMenu`）
**一律用它**，不能用 `todayStr()`。

> ★ 客户端 `utils/format.js` 里有同名函数，两边的 `MENU_CUTOFF_H` 必须**完全一致**。
> 只改一边，22:30 之后点的菜会以一个日期写进库、以另一个日期读出来 ——
> 菜沉在数据库里、界面上不显示，**而且两边都不报错**（最难查的那类故障）。
> `wxml-check.js` 有两条断言专门盯着这件事。
>
> 不受影响的：`publicFamily` 的 `serverDate`、以及 3 天清理用的 `daysAgoStr()` ——
> 那两个跟「菜单属于哪一份」无关，继续用真实的今天。

## action 一览

| action | 说明 |
| --- | --- |
| `createFamily` | 建房间（幂等：已在房间则直接返回） |
| `joinFamily` | 用 6 位房间码加入 |
| `peekFamily` | 加入前预览房间名和人数 |
| `leaveFamily` | 退出（创建者不能退，否则房间会变成孤儿） |
| `renameSelf` | 改自己的称呼 |
| `myFamily` | 查我当前在哪个房间 |
| `addDish` | 加菜（已存在则份数 +1） |
| `addMany` | 一次加多道（摇一摇「三菜一汤」） |
| `setQty` | 改份数，`<=0` 即移除 |
| `setNote` | 改备注 |
| `clearMenu` | 清空今日菜单（**不校验创建者**，家人谁都能清） |
| `listMenu` | 拉今日菜单（watch 的兜底轮询通道） |
